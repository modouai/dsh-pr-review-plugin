# 复审对比（跨轮意见追踪）设计 Spec

> 状态：草案 v6，待评审
> 来源：PR #32 第 4 轮复审暴露的「已修复 8、仍未解决 0」全量误报事故
> 决策记录：
> - 身份判定 = **以上一轮（对比基准轮）意见为主轴逐条判定**（模型对基准轮每条意见强制输出修复状态；无任何系统侧猜测）
> - 基准轮 = 当前轮之前**最近一个生成了最终结论的轮次**（无论是否发布）；未形成结论的轮次跳过，继续向前查找
> - 基准明细 = 该轮**生成结论时冻结**的逐文件明细快照（结论是轮次有效完成的标志；未结论轮次不冻结）
> - 状态词汇 = 保留「已修复 / 仍未解决」，新增「待分析」
> - 通道 = **单通道：审核明细 vs 审核明细，与结论层完全解耦**
> v2：单通道化 + H1 硬性约束（对比与结论层零耦合）
> v3：合入独立读者测试反馈；附录 A 遗留清点
> v4：删除文本相似度与位置邻近兜底（语义内容上字符相似度无意义）
> v5：判定形态重构——上一轮意见逐条强制判定（previousVerdicts）
> v6：「上一轮」精确定义为对比基准轮（最近有最终结论的轮次，跳过无结论轮次）；基准明细在生成结论时冻结进轮次历史
> v7（审查后修订）：判定结果显式持久化到 entry（`baselineVerdicts`），issues 的任何后续改写不再影响对比状态；快照全量冻结、prompt 下发时按文件截断，被截断条目统一落「未判定」；手动改判延后（见 §5）

## 0. 问题陈述

### 0.1 现状缺陷（三层）

| # | 缺陷 | 后果 |
|---|---|---|
| 1 | **跨层比较**：结论前预览用「上一轮**结论**条目」对比「本轮**逐文件明细**」。结论措辞是模型对上轮发现的总结，明细措辞是本轮分析的重新表述——两个层面对同一问题的表述天然不同 | 每开一轮，上一轮结论条目几乎 100% 被判「已修复」，与是否真的修复无关 |
| 2 | **匹配阈值对中文同义重写过严**：匹配要求 `kind + file + 文本相似度 ≥ 0.62`；每轮分析是独立模型调用，point 措辞必然重写 | 实测：语义完全相同的两条发现（同名测试两份），跨轮相似度仅 **0.424**；「line 判断不一致」仅 **0.278**——全部跌破阈值 |
| 3 | **措辞越权**：「已修复」断言的是「问题被修复」，而系统观察到的只是「匹配失败」 | 读者无法区分「真修了 / 误报被否决 / 措辞没接上 / 该文件还没重新分析」 |

### 0.2 事故实例（PR #32 第 3 → 4 轮）

第 4 轮复审对比显示「已修复 8、仍未解决 0」。逐条核对：**8 条没有一条被修复**——其中 2 条（同名测试两份、line 判断不一致）在第 4 轮的发现里原样再次出现（stillOpen），却因相似度 0.424 / 0.278 匹配失败被判「已修复」。

## 1. 目标与非目标

**目标**

- G1 **上一轮意见在本轮不丢失**：上一轮每一条意见在下一轮分析中都被逐条判定，不存在「模型忘了报告导致意见消失」。
- G2 **不被误标为修复**：「已修复」只能来自模型对上一轮意见的**显式判定**（该问题在当前代码中已不存在），绝不由「未再报告」的隐式推断产生。
- G3 **未修复天然即仍未解决**：模型判定「问题仍在」的意见直接进入本轮意见列表，无需任何标记或匹配。
- G4 复审进行中即可实时查看对照，不必等任何额外阶段。
- G5 **复审对比只属于审核工作面**：判定只基于本轮审核内容（逐文件意见），与结论生成阶段零耦合；结论正文与发布评论中不出现任何复审对比内容。

**非目标**

- 不自动验证实现者是否真的修改了代码（那是「实现者反馈」功能的工作）。
- 不改变结论层（blockers / suggestions / nextSteps）自身的生成、合并与发布逻辑。
- 不向结论生成阶段注入复审对比的任何判定结果。

## 2. 术语

| 术语 | 定义 |
|---|---|
| 意见条目（finding） | `{ file, line, severity, point, suggestion }`——逐文件分析产出的单条意见 |
| **对比基准轮**（baseline round） | 当前轮之前**最近一个生成了最终结论的轮次**（无论是否发布）。未形成结论的轮次不是任何轮的基准——向前继续查找 |
| 基准快照（baseline findings） | 基准轮**生成结论时冻结**的逐文件明细（全局连续编号）。是复审对比的唯一对比输入 |
| 逐条判定（previousVerdicts） | 模型对基准快照**每一条**输出的修复状态判定：`fixed` 或 `still-open` |
| 延续条目（carry-over） | 基准快照中判定为 `still-open` 的意见在本轮的对应条目（带 `roundItem` 引用） |
| 复审对比（delta） | 基准快照 ↔ 本轮明细的同层对比；**只存在于审核工作面** |

**硬性约束（H1）**：复审对比的输入只有基准轮与本轮的审核明细；它的输出只渲染在审核工作面（总览卡片、文件详情）。结论生成、结论正文、发布评论一律不读取、不包含复审对比。

## 3. 总体设计：单通道，以基准轮意见为主轴

```
审核工作面（唯一通道）
┌──────────────────────┐
│ 基准轮明细快照          │   基准轮生成结论时冻结
│ baseline findings[]  │   （= 最近一个有最终结论的轮次）
└─────────┬────────────┘
        │ 逐文件分析时随 prompt 下发
        ▼
┌──────────────────────────────┐
│ 模型逐条判定 previousVerdicts  │   基准快照每一条都必须有状态：
│  fixed      → 已修复          │   fixed / still-open
│  still-open → 本轮意见（延续）   │
└───────┬──────────────────────┘
        ▼
┌──────────────────────────────┐
│ 本轮意见 = 延续条目 + 新发现      │
└───────┬──────────────────────┘
        ▼
  总览「复审对比」卡片 · 文件详情「上轮即有」标记
  （仅审核工作面渲染；结论与发布评论不出现）
```

- 判定发生在**逐文件分析**时（不是结论阶段）——「该文件的分析」本身就要回答「基准轮提的问题现在怎么样了」；
- 基准轮的选取**跳过未形成结论的轮次**：一轮审核只有生成了最终结论才被视为有效完成，其明细才冻结为可对比的基准；中间的无结论轮次向前跳过；
- 结论生成**不是**对比的触发点，也**不改变**本轮已确定的对比状态——基准快照恰恰是在结论生成时为**下一轮**准备的；
- 发布评论不含复审对比段落；复审对比是内部工作面信息，不是对外发布的审查内容。

## 4. 判定机制：基准轮意见逐条强制判定

### 4.1 prompt 形态

逐文件分析的 prompt 在现有内容（diff、完整文件、分析要求）之外，新增一节（内容 = 基准快照中该文件相关的条目，按基准快照全局编号）：

```
## 基准轮审查意见（本轮必须逐条判定修复状态）
1. [block] 空指针风险（行 2）—— 建议：先判空再取值
2. [suggest] 命名不清（行 4）—— 建议：改成 camelCase

对上面每一条意见，结合当前代码逐条判定：该问题在本次改动后是否仍存在。
- 仍存在 → 输出 "status": "still-open"，并把它作为一条审查意见写入 issues
  （severity 沿用或按当前代码修正，point 用当前代码的表述重写，line 更新为当前行号），
  同时带 "roundItem": <基准快照序号>；
- 已修复 / 不再存在 → 输出 "status": "fixed"，不要把它写入 issues。
基准轮有 N 条意见，previousVerdicts 必须恰好包含 N 条判定，一条都不能少。
本轮新发现的问题照常写入 issues（不带 roundItem）。
```

模型输出（在现有 JSON 结构上新增一个字段）：

```json
{
  "summary": "…", "logic": "…", "walkthrough": […], "changes": "…",
  "previousVerdicts": [
    { "index": 1, "status": "fixed" },
    { "index": 2, "status": "still-open", "point": "变量名 userInfo 拼写不一致", "line": 4, "severity": "suggest" }
  ],
  "concerns": [ …新发现候选（走取证复审）… ],
  "evidenceNeeds": […],
  "verdict": "…"
}
```

### 4.2 落库规则

| 基准快照条目的判定 | 处理 |
|---|---|
| `still-open` | 成为一条本轮意见：`{ severity, point, line, suggestion }` 取模型更新值（未提供的沿用基准轮），并带 `roundItem` 引用；**不经过取证复审**——它是基准轮已确认的意见，本轮只需确认其存续，不是新候选 |
| `fixed` | 不进本轮意见；状态记「已修复」 |
| **无判定**（previousVerdicts 缺失该条） | **保守落「仍未解决」**：沿用基准轮的 point/line/severity 原样进入本轮意见（`roundItem` 引用），并标注「模型未逐条判定」。宁可持续追问，不可静默消失——这实现 G1「上一轮意见在本轮不丢失」 |

`concerns`（新发现候选）照常走取证复审；`previousVerdicts` 判出的延续条目绕过复审（基准轮已确认过，本轮只确认存续）。

### 4.3 输出的合法性校验

- `previousVerdicts` 的 `index` 越界 / 重复 → 忽略非法条目；
- **数量校验**：`previousVerdicts` 覆盖数 < 基准快照条目数 → 缺失条目按 4.2「无判定」保守落「仍未解决」；
- `still-open` 未附 point 时沿用基准轮原文；severity 非法时沿用基准轮。

### 4.4 为什么这个形态消除了 v4 的两个残余风险

| v4 风险（新意见自由报告 + 可选标注） | v5 形态（上一轮逐条强制判定） |
|---|---|
| 模型漏标延续 → 该条被隐式判「已修复」 | 不存在漏标：每条上一轮意见都被强制判定；缺失本身也被保守处理（落「仍未解决」） |
| 语义等价靠模型标注自觉 | 「是否修复」是针对具体上一轮意见的**对照判定**，比「自由报告 + 事后认领」聚焦得多 |

## 5. 状态词汇与判定规则

保留现有词汇「已修复 / 仍未解决」，新增「待分析」。每条基准快照条目的状态：

| 状态 | 判定条件 | 语义 |
|---|---|---|
| **已修复**（resolved） | 模型对该条显式输出 `fixed` | 模型对照当前代码判定问题已不存在——**唯一**的已修复来源 |
| **仍未解决**（still-open） | 模型输出 `still-open`（对应本轮延续条目） | 问题仍在 |
| **未判定**（undetermined） | 模型没有判定该条（漏判、prompt 截断、旧缓存无判定数据、零判定折叠） | 状态未知；展示并入「仍未解决」并标注「模型未逐条判定」，**绝不判「已修复」** |
| **待分析**（pending） | 本轮该文件尚未（重新）分析 | 状态未定，**不计入已修复** |

规则要点：

- 「该文件已完成分析」是进入判定的前置条件——分析没覆盖就宣称修复是最严重的越权；此条件是**逐文件**的，不是全局的；
- **file 为空的基准快照条目**（未定位到文件）：随明细一起下发与判定；基准快照中无 file 的条目单独成组，其「已修复」的前置条件是本轮**全部分析完成**且模型未延续它；
- **被截断（未进 prompt）的基准快照条目**：模型不可能判定它——状态为「未判定」（undetermined，面板标注「模型未逐条判定」），**绝不判「已修复」**；快照全量冻结，仅 prompt 下发时按文件截断并显式声明；
- 复审否决（候选被 verifier 以低置信度丢弃——现有两遍管线的概念）属于**新发现**的处理，不影响上一轮条目的判定；
- **（v7 延后）手动改判**：面板级「已修复→仍未解决」入口与审计落盘本轮不实现，列为后续工作；误判的纠正是下一轮重新分析（以及把不属于该文件的条目从该文件意见中移除，避免快照继承）；
- **H1 的推论**：结论的生成与否、结论的条目内容，均不参与上述任何判定。

## 6. 数据形状

```ts
// 基准快照：在基准轮「生成结论」时冻结，写入该轮的 round entry（§7）。
// baselineRoundOf(record)：从当前轮向前找最近的 conclusions.length > 0 的轮次，取其快照；
// 没有任何有结论的轮次 → 无基准，不渲染复审对比。
type BaselineFindings = FindingSnapshot[]   // 全局连续编号 1..N（跨文件连续）

type FindingSnapshot = {
  index: number,                  // 全局 1-based 序号（跨文件连续）
  file: string,
  severity: 'block' | 'suggest',
  point: string,
  line: number,                   // 0 = 无行号
  suggestion: string,
}

// 模型输出：基准意见逐条判定
type PreviousVerdict = {
  index: number,                  // 对应基准快照全局序号
  status: 'fixed' | 'still-open',
  // still-open 时可附更新值（缺省沿用基准轮）：
  point?: string,
  line?: number,
  severity?: 'block' | 'suggest',
  suggestion?: string,
}

// 文件分析的 entry 额外持有判定结果（分析时落库、随缓存持久化；对比只读它）
type AnalysisEntry = {
  status: 'done', explanation: Explanation, chat: [...], updatedAt: number,
  baselineVerdicts: PreviousVerdict[] | null,   // null = 分析时无基准
}

// 本轮意见条目（落库）
type Issue = {
  severity: 'block' | 'suggest',
  point: string,
  suggestion: string,
  line: number,
  roundItem?: number,             // 基准快照全局序号——存在即延续条目（未经复审的新发现无此字段）
}

// 复审对比聚合（实时计算，不持久化）
type FindingsDelta = {
  resolved: FindingSnapshot[],    // 已修复（模型显式判定）
  stillOpen: { previous: FindingSnapshot, current?: Issue }[],  // 仍未解决
  undetermined: FindingSnapshot[],// 模型未逐条判定（保守落仍未解决）
  pending: FindingSnapshot[],     // 待分析
}
```

快照**全量冻结**（不丢任何条目）；仅 prompt 下发时按文件截断到 10 条（block 优先、line 升序、其余保持原序），并在段内显式声明「上一轮意见已截断」。被截断的条目**状态为「未判定」**（undetermined），绝不静默消失、绝不判「已修复」。

## 7. 各时点行为

| 时点 | 行为 |
|---|---|
| **生成结论** | **冻结基准快照**：该轮逐文件明细经 findingsOf 展平 + 全局编号，写入该轮 round entry——这是下一轮（或跳过若干无结论轮次后的某一轮）的对比基准。结论生成本身不计算、不改变任何对比状态 |
| **开新一轮** | 无快照动作；本轮全部基准条目初始为「待分析」。`baselineRoundOf` 向前跳过无结论轮次选定基准 |
| **单文件分析完成** | `previousVerdicts` 落库：`fixed` → 该条「已修复」；`still-open` → 延续条目进本轮意见；**无判定 → 保守落「仍未解决」**；该文件的对比状态即刻可见（总览卡片实时更新） |
| **该文件分析失败** | 该文件的基准条目保持「待分析」 |
| **结论生成之后（本轮内）** | 对比状态不变——本轮已确定的对比不因结论被重算或改写 |
| **发布** | **无行为**——发布评论不含任何对比内容 |

## 8. 展示

| 位置 | 内容 |
|---|---|
| 总览「复审对比」卡片 | `已修复 X · 仍未解决 Y · 待分析 Z`（Z>0 或 Y 含未判定时展示明细）+ 各态列表（点开可见上一轮原文与本轮对应条目） |
| 文件详情 | 延续条目加「上轮即有」轻标记（可选，不阻塞） |
| 结论正文 / 发布评论 | **不渲染任何复审对比内容**（H1） |

## 9. 边界情况

| 场景 | 行为 |
|---|---|
| 相邻上一轮没有结论（分析中断 / 中途开轮） | **跳过它，继续向前查找**最近的「生成过最终结论」的轮次作为基准（`baselineRoundOf`）；无结论轮次的明细不参与对比 |
| 连续多个无结论轮次 | 同上——一路向前直到找到有结论的轮次；历史中从无结论 → 无基准，不渲染对比卡片 |
| 基准轮结论后来被改写（新结论版本） | 基准快照在每次生成结论时刷新（该轮最新结论时刻的明细）；结论生成之后的明细改动不回溯快照 |
| 上一轮条目 `file` 为空（未定位） | 随快照单独成组照常下发与判定（模型可结合全 PR 判断）；「已修复」前置条件为本轮全部分析完成（见 §5） |
| 基准快照为空（基准轮结论时刻明细为空 / 首轮） | 不渲染对比卡片；不存在误报 |
| `still-open` 指向其他文件的基准条目（文件重命名） | 允许——判定以快照全局序号编址，模型可跨文件延续 |
| `previousVerdicts` 缺失部分条目 | 缺失条目保守落「仍未解决」（沿用基准轮原文），面板标注「模型未逐条判定」；**绝不判「已修复」** |
| 模型输出非法 `status` / `index` 越界 / 重复 | 忽略非法条目，按「无判定」保守处理 |
| 快照条目被截断（>10 条/文件） | 快照全量保留；不下发 prompt → 状态「未判定」（undetermined），绝不判已修复；prompt 声明截断 |
| 该文件本轮分析失败（error） | 状态保持「待分析」，不计入已修复 |
| 延续条目与新发现候选重复（verifier 的 extraIssues 与延续条目讲同一问题） | 接受重复（罕见）；不合并——延续条目保持其基准轮级别，新发现走正常复审 |
| 用户手动改判 | **v7 延后**：本轮不提供入口；误判纠正走下一轮重新分析 |
| 结论在对比未完成时生成（部分文件仍待分析） | 结论正常生成；本轮已确定的对比状态不受影响；同时本轮结论生成会冻结新的基准快照供后续轮使用 |

## 10. 验收标准

1. **上一轮意见零丢失**：上一轮 N 条意见，本轮分析完成后每条都有状态（fixed / still-open）；不存在「无判定即消失」的条目（缺失判定落「未判定」（undetermined）并有标注）。
2. **「已修复」只来自显式判定**：模型未输出 `fixed` 的上一轮条目，任何代码路径都不得落「已修复」。
3. **未修复天然延续**：模型判 `still-open` 的条目自动进入本轮意见列表（roundItem 引用、表述/行号可更新），不需要 carryOver 标注或系统匹配；**它不经过取证复审**。
4. **同义重写免疫**：模型对本轮 point 的重写不影响状态——状态挂在 previousVerdicts 上，与文本相似度无关。
5. **结论零耦合**：结论生成前后，复审对比的状态与展示完全不变；结论正文与发布评论中不出现任何「已修复 / 仍未解决」对比内容（代码库中不存在「结论条目 vs 明细条目」或「明细条目 vs 结论条目」的比较路径）。
6. **prompt 含上一轮意见**：explain prompt 在有快照时包含「上一轮审查意见（逐条判定）」段落（全局编号 + 强制逐条要求 + 截断声明）；无快照时不含该段落，也不要求 `previousVerdicts`。
7. `pnpm test` 通过；新增用例覆盖：逐条判定落库（fixed / still-open / 表述更新）、缺失判定落「未判定」（undetermined）、非法 status/index 忽略、still-open 绕过取证复审、基准轮选取跳过无结论轮次、结论生成冻结基准快照、快照截断落「未判定」、改写 issues 不改变对比状态、结论生成不影响已确定对比状态。
